How to use this sheet

  1. Run the sections in order — later cases depend on orders created in earlier ones.
  2. For each row, perform the steps and compare against Expected Result.
  3. If the app behaves exactly as expected → tick P and leave Actual empty.
  4. If it differs in any way → tick F and write what actually happened in Actual / Bug note. Add a bug number (B-01, B-02 …) and copy it into the Bug Log on the last page.
  5. If a case cannot be run (feature off, no data, blocked) → write N/A plus the reason in Actual.
  6. Take a screenshot for every failure and name it with the bug number.

Legend

CRIT Critical path — a failure here blocks the release. NEG Negative test — the app must refuse or hide something.
CFG Depends on a setting/feature flag. If the feature is off, mark N/A. P / F = Pass / Fail tick boxes.
Before you start — preconditions 1. Two separate accounts are needed: one plain Staff (Role Profile "Jarz POS Staff") and one Line Manager (Role Profile "Jarz POS Line Manager"). Do not test both personas from one login.
2. Both accounts must be linked to a POS Profile via the POS Profile User table, and the branch must have items, at least one bundle, delivery slots, one courier, and at least one expense account configured.
3. The Staff account must have Require POS Shift enabled on the User record, otherwise the whole shift section is not applicable.
4. Always fully log out (and hard-refresh on web) when switching between the two personas — a stale session hides permission bugs.
5. Use a clearly fake customer name (e.g. "TEST — your name") for every order you create so the data can be cleaned up afterwards.
Scope of this version The Delivery Trips section (creating a multi-order trip, the Trips screen, marking a trip delivered) is excluded from this version by request. The step of sending a single order out for delivery with a courier from the Kanban board is still covered (cases ST-KAN-16 / 17), because Courier Balances and End Shift cannot be tested without it.

Who runs this section, and with what access This section cannot be done from the POS app — the app never shows the ledger, by design. It needs read access to ERPNext Desk (/desk) with permission to view Sales Invoice, Payment Entry, Journal Entry, GL Entry, Delivery Note and Courier Transaction.
If the tester does not have that access, this section must be run by an accountant or a JARZ Manager working from the invoice numbers she recorded in Section 1. Do not skip it — Sections 1–3 can all pass on a build that posts every order to the wrong account.
How to look up a voucher's ledger Open /desk → search the invoice number → open the Sales Invoice → menu → Ledger. Or open the GL Entry list and filter by Voucher No.
Account names carry a company suffix in this system (e.g. Creditors - J, Courier Outstanding - J) — match on the leading name, ignore the suffix.
